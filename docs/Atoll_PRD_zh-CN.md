## 1. 产品概述

### 1.1 产品定位

Atoll 将 MacBook 刘海及屏幕顶部空间改造成一个随用随现的桌面控制中枢。用户无需切换应用，即可完成媒体控制、系统状态查看、计时、日程提醒、文件暂存、剪贴板调用、颜色拾取、AI 问答和开发工具操作。

产品的核心价值不是“把 iPhone 灵动岛搬到 Mac”，而是用系统级、低打扰的交互入口减少上下文切换：空闲时保持隐形，事件发生时提供即时反馈，用户主动悬停或使用快捷键时再展开完整工具。

### 1.2 核心价值主张

1. **低打扰**：关闭状态只显示必要反馈，不持续占用桌面空间。
2. **即时可达**：通过悬停、手势、快捷键或系统事件快速唤起。
3. **系统融合**：统一媒体、音量、亮度、电量、蓝牙、专注模式、录屏等分散反馈。
4. **模块组合**：用户按角色和习惯开启功能，避免所有能力同时堆叠。
5. **本地优先**：设置、历史记录和多数系统数据在本机处理；外部请求必须清楚说明用途。
6. **可扩展**：通过扩展授权机制接入第三方 Live Activity、锁屏组件和刘海体验。

### 1.3 产品目标

- 让用户在 3 分钟内完成首次配置，并成功体验至少一个核心场景。
- 把媒体控制、系统反馈和高频小工具统一在屏幕顶部入口中。
- 在常驻运行前提下保持低 CPU、低内存占用和稳定动画。
- 对每项敏感权限说明“为什么需要、何时使用、拒绝后影响什么”。
- 建立可持续迭代的模块边界、验收标准和发布质量门槛。

### 1.4 非目标

- 不替代完整的音乐、日历、终端、笔记或 AI 客户端。
- 不建设云端账户、社交关系或跨用户协作平台。
- 不在未获得明确同意时上传剪贴板、屏幕截图、文件内容或使用记录。
- 不承诺所有第三方媒体应用、显示器控制工具和私有 macOS API 永久兼容。
- 不以堆叠功能数量作为版本成功标准；默认体验应保持克制。

## 2. 目标用户与使用场景

### 2.1 用户画像

| 用户 | 核心诉求 | 高频功能 | 主要顾虑 |
|---|---|---|---|
| 日常 Mac 用户 | 更直观地查看系统状态和控制媒体 | 媒体、音量/亮度、电池、蓝牙、计时器 | 设置复杂、耗电、常驻打扰 |
| 开发者 | 减少工具切换并快速查看资源/AI 配额 | Stats、Terminal、LLM Usage、Clipboard、Shelf | 性能、隐私、权限、快捷键冲突 |
| 设计师/内容创作者 | 快速取色、暂存素材、控制录屏和媒体 | Color Picker、Shelf、Clipboard、Screen Recording | 截图污染、色值准确性、素材安全 |
| 学生/知识工作者 | 管理日程、提醒、计时和笔记 | Calendar、Reminder、Timer、Notes | 信息过载、提醒不准、数据丢失 |
| 高度定制用户 | 个性化显示、动画与外接屏行为 | Appearance、Lock Screen、HUD、Extensions | 升级后配置丢失、兼容性下降 |

### 2.2 核心任务（Jobs to Be Done）

- 当我正在全屏工作时，我希望不离开当前应用就能切歌、调节音量或查看下一场会议。
- 当系统状态发生变化时，我希望得到短暂、明确且不遮挡内容的反馈。
- 当我临时复制文本、图片或文件时，我希望稍后能快速找回并拖到目标应用。
- 当我需要短时计时、查看资源占用或询问 AI 时，我希望从固定入口直接完成。
- 当我锁屏或连接外设时，我希望继续看到必要状态，但不暴露敏感内容。
- 当某项能力需要系统权限时，我希望先理解用途，并能在拒绝后继续使用其他功能。

### 2.3 典型场景

1. 用户播放 Spotify，刘海显示歌曲缩略信息；悬停后展开播放控制、歌词、音量和输出设备。
2. 用户按音量键，原生 HUD 被 Atoll 的统一 HUD 替代；几秒后自动收起。
3. 用户开始屏幕录制，顶部出现录制指示和可选停止按钮；截图时 Atoll 可按设置隐藏。
4. 用户将多个文件拖到 Shelf，稍后批量拖出、Quick Look、压缩或分享。
5. 用户按 `⌘⇧V` 打开剪贴板历史，将富文本或图片拖入其他应用。
6. 用户锁屏后看到音乐、计时、天气、日历和专注状态组件，并可控制媒体。
7. 开发者打开 Stats 或 LLM Usage，查看 CPU、内存及本机 AI 工具配额。

## 3. 产品原则

1. **事件优先，工具次之**：系统事件反馈优先于常驻装饰；工具只在用户主动唤起时展开。
2. **默认可用，按需增强**：拒绝非必要权限后，基础媒体与设置仍应可用。
3. **单一状态源**：同一媒体、计时或系统事件在刘海、浮窗、锁屏中应保持一致。
4. **失败可降级**：第三方 API、私有 API 或权限不可用时，降级到基础能力，不得拖垮主进程。
5. **配置可恢复**：升级、重装和通道切换不应静默丢失用户偏好。
6. **敏感数据最小化**：能在本地完成的处理不上传；必须联网时只发送完成任务所需的信息。
7. **动效服务于反馈**：动效需表达状态变化，不得以牺牲响应速度和功耗为代价。

## 5. 核心用户流程

### 5.1 首次启动

1. 启动应用，展示欢迎页和核心价值说明。
2. 用户可授权或跳过相机权限。
3. 用户可授权或跳过日历/提醒权限。
4. 用户选择媒体来源：Apple Music、Spotify、系统 Now Playing、YouTube Music、Amazon Music、TIDAL 或 Cider。
5. 用户选择一个或多个使用画像：开发者、设计师、轻量使用、学生。
6. 系统按画像应用推荐功能组合。
7. 用户进入完成页，可直接开始或打开设置。
8. 后续功能需要额外权限时，采用上下文授权，不在首次启动一次性索取所有权限。

### 5.2 日常展开与关闭

1. 用户将指针移入刘海热区，达到最短悬停时间后展开。
2. 系统默认进入上次有效标签或 Home；若该标签已关闭，则回退到首个可用标签。
3. 用户切换标签或执行工具操作。
4. 指针离开且不存在拖拽、Popover、歌词滚动等抑制条件时，延时关闭。
5. 用户也可使用双指手势、滚动手势或全局快捷键开关刘海。

### 5.3 媒体控制

1. 监听所选媒体来源并获取歌曲、艺人、封面、时长和播放状态。
2. 关闭态显示媒体摘要或 Sneak Peek。
3. 展开后提供播放/暂停、上一首/下一首或前后 10 秒、进度、随机/循环、输出设备和音量。
4. 开启歌词时获取并同步滚动；无可靠元数据或无匹配结果时显示明确空态。
5. 媒体源退出或数据失效后，清理旧封面和控制状态，按设置自动隐藏播放器。

### 5.4 Shelf 文件流转

1. 用户把一个或多个文件拖入 Shelf，或通过 `open -a Atoll /path/to/file` 添加。
2. 系统保存文件引用并展示缩略图、名称和类型。
3. 用户可单选、多选、框选、Quick Look、打开、定位、复制路径、压缩、分享或移除引用。
4. 默认拖出是复制语义；只有显式开启“允许移动”后才可移动原文件。
5. 文件不可访问或已被删除时保留可理解的失效态，不得卡住界面。

### 5.5 屏幕助手

1. 用户通过按钮或 `⌘⇧A` 打开 Screen Assistant。
2. 用户选择截取区域、使用现有截图、输入文字或录制语音。
3. 系统在本地生成请求预览，明确显示将发送的内容和目标提供商。
4. 用户确认后调用 Gemini、OpenAI、Claude、Groq 或本地模型端点。
5. 结果以对话形式展示；失败时保留用户输入并允许重试或切换模型。

## 7. 权限与隐私要求

### 7.1 权限矩阵

| 权限/访问 | 使用场景 | 拒绝后的降级 | 产品要求 |
|---|---|---|---|
| 辅助功能 | 拦截媒体键、替代 HUD、Clock 计时镜像、部分全屏判断 | 使用 macOS 原生 HUD；系统计时镜像不可用 | 仅在启用相关功能时请求 |

| 麦克风 | AI 语音提问 | 仅文字/图片输入 | 录音期间显示明确状态和停止入口 |

| 蓝牙 | 设备连接、电量和听音模式 | 不显示蓝牙 HUD | 不扫描或上传无关设备信息 |
| 位置 | 锁屏天气 | 允许手动地点或隐藏天气 | 提供手动城市作为替代方案 |
| 音频捕获 | 实时波形/频谱 | 显示普通进度条 | 关闭功能后立即停止捕获 |
| Documents/Downloads | Shelf 文件访问、下载监听 | 仅访问用户显式选择的文件 | 优先使用最小目录授权 |
| Full Disk Access | Shelf 全局模式、自定义 Focus、部分本机用量读取 | 保留有限模式 | 必须说明不是基础运行必需权限 |
| 网络 | 天气、歌词、AI、Spotify OAuth、更新 | 展示离线/不可用状态 | 使用域名白名单和合理超时 |

### 7.2 数据分类

| 等级 | 数据 | 默认策略 |
|---|---|---|
| 高敏感 | API Key、OAuth Token、剪贴板、截图、录音、笔记、文件路径 | Keychain 或本地受保护存储；不得写普通日志 |
| 中敏感 | 日历标题、提醒、媒体历史、位置、AI 用量 | 本地处理；联网前说明用途并最小化字段 |
| 低敏感 | UI 偏好、颜色、窗口尺寸、功能开关 | UserDefaults/Defaults 持久化 |
| 公开 | 版本号、更新通道、扩展清单 | 可用于更新和兼容检查 |

### 7.3 外部服务边界

- AI 请求仅发送给用户选定的提供商或本地端点。
- Spotify 收藏功能使用官方 OAuth 2.0 PKCE；Token 存入 Keychain。
- 歌词请求只发送匹配所需的歌曲元数据；关闭歌词后不得继续请求。
- 天气服务只发送必要位置精度；应支持手动地点和关闭定位。
- 更新只访问当前通道对应的签名 Appcast 与发布包。
- 产品默认不增加行为分析 SDK。若后续需要遥测，必须提供显式选择、数据清单和关闭入口。

- 每个破坏性配置变更必须提供一次性、幂等迁移。

- Stable、Beta、Alpha、Nightly 共用配置时，低版本不得因未知字段崩溃。

## 9. 非功能需求

### 9.1 性能

以下为后续版本的目标值，需通过 Instruments 和自动化基准确认：

- 空闲 5 分钟后平均 CPU ≤ 1%，95 分位 ≤ 2%。
- 基础功能常驻内存目标 ≤ 220 MB；开启波形、Stats 或锁屏动态封面时分别记录增量。
- 刘海展开首帧响应 ≤ 100 ms，完整展开动画 ≤ 350 ms。
- 展开/关闭动画在 60 Hz 屏幕上平均 ≥ 55 FPS，不出现连续 3 帧以上明显卡顿。
- Stats 默认 1 秒采样；标签关闭或功能停用后停止高频采样。
- 文件、蓝牙、进程和磁盘查询不得同步阻塞主线程超过 16 ms。

### 9.2 稳定性

- 稳定版崩溃自由会话目标 ≥ 99.5%。
- 连续运行 24 小时后不存在明显内存持续增长、僵尸进程或事件监听器叠加。
- 第三方应用退出、网络断开、权限撤销、显示器热插拔不得导致主进程崩溃。
- 应用退出后必须恢复系统 HUD、媒体键和临时监听状态。

### 9.3 兼容性

- 最低构建目标以 Xcode 工程为准：macOS 14.6。
- 重点测试 macOS 15 与 macOS 26；涉及私有 API 的能力需具备运行时可用性检测。
- 覆盖带刘海 MacBook、无刘海 Mac、单外接屏、多外接屏及不同缩放比例。
- 支持 Apple Silicon；发布包如继续提供 Intel 架构，应纳入同等冒烟测试。

### 9.4 可访问性

- 所有可点击图标提供 VoiceOver Label、Help 和足够的点击区域。
- 主要流程可使用键盘完成；焦点顺序与视觉顺序一致。
- 不只依赖颜色表达状态，支持“减少动态效果”和高对比度。
- 动态文本应避免在关键控制中被截断；长标题使用缩放、换行或 Marquee 的明确规则。

### 9.5 本地化

- 英文为源语言；简体中文和繁体中文进入发布必测语言。
- 新增文案不得硬编码，必须进入 String Catalog。
- 发布前检查缺失翻译、占位符一致性、复数规则和布局溢出。
- 权限说明、隐私文案和高风险操作必须优先完成中文本地化。

## 11. 建议迭代路线图

### 11.1 Phase 0：建立可安全迭代的基线（P0）

目标：先解决安全、权限、配置和发布质量问题，避免在不稳固的底座上继续堆功能。

1. 将 Screen Assistant 的云端 API Key 从 Defaults 迁移到 Keychain。
2. 建立权限与功能健康中心，统一权限状态、受影响功能和修复入口。
3. 增加配置导出/导入、迁移快照和一键恢复默认值。
4. 建立 Live Activity 优先级、抢占和恢复机制。
5. 为剪贴板增加暂停、清空、应用排除和敏感来源保护。
6. 建立稳定版发布门禁：签名、公证、单测、UI 冒烟、权限回归、性能基线。
7. 补充脱敏诊断包，降低用户反馈问题的排查成本。

### 11.2 Phase 1：降低学习成本并提升日常留存（P1）

目标：让用户更快找到适合自己的功能，并让高频操作更顺手。

1. 首次引导支持中断恢复和“稍后配置”。
2. 设置首页增加推荐配置、当前问题和最近使用功能。
3. 标签支持用户排序、隐藏、分组和一键恢复推荐布局。
4. 增加统一命令面板，搜索功能、设置和操作，并支持自定义快捷键。
5. 完善离线、权限不足和第三方服务失败的空态与恢复动作。
6. 统一刘海、浮窗和锁屏媒体组件的控制槽位与状态逻辑。

### 11.3 Phase 2：扩展生态与专业能力（P2）

目标：在稳定核心之上扩展差异化，而不是扩大默认复杂度。

1. 发布 Atoll ExtensionKit 文档、示例项目、兼容矩阵和扩展权限规范。
2. 增加本地扩展目录和开发者模式，默认不自动执行未知扩展。
3. 为 Shelf、Notes、Clipboard 提供可选的本地加密存储。
4. 为设计师、开发者、学生提供可分享的配置模板，但不包含隐私数据。
5. 探索插件化 AI Provider，核心应用只保留统一请求与权限层。

## 12. 验收与发布门槛

### 12.1 每项需求的完成定义（Definition of Done）

- PRD 中有唯一需求 ID、范围、优先级和验收标准。
- 交互稿覆盖正常、加载、空、错误、权限拒绝和恢复状态。
- 代码通过编译、静态检查、相关单元测试和 UI 冒烟测试。
- 新设置项有默认值、迁移规则、重置规则和本地化文案。
- 新权限或联网行为同步更新权限矩阵和隐私说明。
- 新功能关闭后不残留高频 Timer、Observer、子进程或网络任务。
- 对 CPU、内存、动画和主线程阻塞进行与风险相称的验证。
- CHANGELOG 标注 Added、Changed、Fixed 或 Removed，并注明影响范围。

### 12.2 稳定版回归矩阵

| 维度 | 最低覆盖 |
|---|---|
| 系统 | macOS 14.6、15.x、26.x |
| 设备 | 带刘海 MacBook、无刘海 Mac、外接显示器 |
| 显示 | 单屏、多屏、不同缩放、全屏、Spaces 切换、锁屏/解锁 |

### 12.3 核心验收场景

1. **权限降级**：在无辅助功能权限下启动，Atoll 不崩溃，媒体与设置可用，HUD 明确提示并回退系统行为。
2. **显示器热插拔**：展开状态连接/断开外接屏，窗口不会丢失、越界或残留不可点击区域。
3. **媒体切源**：播放 Apple Music 后切到 Spotify，2 秒内完成状态切换，不显示旧封面或错误控制目标。
4. **拖拽安全**：默认设置下从 Shelf 拖出文件，源文件位置不改变；只移除 Shelf 引用也不删除源文件。
5. **隐私保护**：开启隐藏截屏后，系统截图不包含 Atoll；Screen Assistant 发送前能检查待上传内容。
6. **退出恢复**：在自定义 HUD 开启时退出或升级 Atoll，macOS 原生 HUD 与硬件键恢复可用。
7. **长时稳定**：连续运行 24 小时并多次开关各标签，无监听器倍增、明显内存增长或僵尸子进程。

## 13. 风险与待决策项

| 风险/问题 | 影响 | 建议决策 |
|---|---|---|
| 大量系统行为依赖私有 API 或系统实现细节 | macOS 更新后可能失效 | 每项私有能力增加运行时检测、降级和版本回归 |
| 产品能力过多，默认界面容易复杂 | 新用户学习成本高 | 默认只开启核心模块，按画像推荐，支持模块排序/隐藏 |
| AI Key 当前定义在普通偏好存储中 | 凭据泄露风险 | P0 迁移 Keychain，并做旧值清除验证 |
| Info.plist 允许任意网络加载 | 扩大网络攻击面 | 收紧 ATS，仅为确有需要的域名添加例外 |
| 剪贴板、截图、笔记和文件路径高度敏感 | 隐私与信任风险 | 默认最小保存、应用排除、快速暂停、清空及加密选项 |
| Full Disk Access 覆盖范围过大 | 用户拒绝率和信任成本高 | 拆分有限模式与全局模式，默认有限模式 |
| Stable 与 dev/Unreleased 能力边界复杂 | PRD、测试和发布容易错位 | 每个需求绑定版本、分支和 Feature Flag |
| 中英文权限文案存在不一致或拼写问题 | 审核与信任风险 | 发布前统一权限文案并纳入自动测试 |
| 扩展 RPC/XPC 增加攻击面 | 本机恶意应用可能滥用 | 强身份、最小授权、限流、审计和立即撤销 |

### 13.1 需要产品负责人确认

1. Atoll 的第一核心场景是媒体控制，还是“顶部桌面工具平台”？这会决定默认模块和首页信息密度。
2. 是否长期支持 macOS 14.6，还是聚焦 macOS 15/26 以减少兼容成本？
3. Stable 版本是否继续同时支持 Intel，还是后续仅发布 Apple Silicon？
4. Screen Assistant 是核心能力还是可选插件？是否接受云端 AI 请求带来的隐私和维护成本？
5. 是否需要匿名遥测？若需要，数据范围、保存周期和同意方式必须先确定。
6. 扩展生态是面向公开开发者还是仅供内部/精选合作方？
